# 適用性、例外與證據標準

## 判定次序（每一條）
1. 識別系統功能與資料流：必須明確回答是否具有此控制對象。
2. 查明控制責任：程式碼、IdP、API Gateway、Reverse Proxy、主機、DB、維運或第三方。
3. 查明已生效強制要求、契約及核准公司基準：缺少適用規範時，不得推定法定義務。
4. 搜尋程式碼與部署證據，逐項追溯實際控制及對抗測試。
5. 依 Pass/Fail/Review/N/A 判定，寫入與判定一致的證據及解釋。
6. 如果不符合或存在高風險疑慮，提出 Finding 及改善措施；若尚待確認，不應偽裝成已證實漏洞。

## 四種狀態
- Pass：適用控制已取得必要佐證與測試，不能只是沒有查到漏洞。
- Fail：控制適用且有明確違反；跨層及替代控制已核查。
- Review：原始碼/主機/政策/測試證據不足。
- N/A：功能不具備，且沒有其他適用義務，附明確理由。

## 風險接受與法定免執行
- 風險接受不會把 Fail 自動改成 Pass，應在報告保留不符合與獨立例外紀錄。
- 例外需載明規則編號、風險、批准者、接受者、補償控制、起訖日期及複核週期。
- 若屬資通安全責任等級分級辦法第 11 條法定免執行，須依當前法條經主管／權責機關完成程序。
- 超過有效期限的例外視為無有效豁免，重新審查。

## 批准與追溯
- 新增規則／變更 Pass/Fail 門檻：須資安簽核及基準測試比較。
- 系統權責人對適用與業務流程簽認，資安人員覆核高風險與特例。
- 規範證據包括來源 URL、版本、發布/施行日、法條或 ASVS 需求號、核對者。
